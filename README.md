# THINKLET Hand Mouse

USB接続のTHINKLETを首にかけ、カメラに映した片手でMacのマウスを操作する試作アプリです。

## 公開ソースとローカルデータ

このリポジトリにはソースコード、起動・ビルドスクリプト、テストのみを含めます。署名用の秘密鍵・証明書・パスワード（`.local-signing/`）、生成物（`build/`・`outputs/`）、診断ログ、撮影画像、端末固有の設定は公開しません。これらは `.gitignore` で除外しています。

別のMacでは `Install.command` からその環境専用の署名を作成してください。開発者の署名鍵を共有する必要はありません。Androidの `android` というパスワードは開発用キーストアの標準値であり、認証サービスの秘密情報ではありません。生成されたキーストア自体は公開しません。

## 起動

1. THINKLETをデータ対応USBケーブルで接続します。
2. 初回と更新時は、既存のアプリを⌘Qで終了して `Install.command` を開きます。プロジェクト専用の署名を設定し、ビルド・検証したアプリを `/Applications/THINKLET Hand Mouse.app` に配置して起動します。失敗時は旧版を置き換えません。次回からはこのインストール先のアプリをDockから起動できます。`Start.command` も同じ場所を開き、古い版ならインストーラーへ進みます。開発用 `outputs` を直接開いて別々の許可を設定する運用はやめてください。
3. プレビューで手が見えることを確認します。左右反転は初期設定でオフです。必要に応じて「左右反転」「回転」を選びます。
4. 「操作開始」を押します。初回はmacOSの「システム設定 → プライバシーとセキュリティ → アクセシビリティ」でインストールされた **THINKLET Hand Mouse** を許可します。以前の開発版の登録が残っている場合は古い項目を削除し、インストール先のアプリを追加してオンにしてください。開始要求は保持され、許可と映像が揃うと開始します。「開始待ちを解除」で取り消せます。macOSから再起動を求められた場合は、アプリを終了して開き直してください。
5. 親指を指先から離した状態で手を映してから操作してください。

### 認識の見える化

映像に21関節の点と指の骨格を重ねます。親指はオレンジ、人差し指は水色、中指は緑、薬指はピンク、小指は紫です。信頼度が低い関節は描画しません。人差し指先の丸がポインターの基準です。「骨格を表示」で表示を切り替えられます。

映像の下には認識できた関節数と、つまみ・クリック・ドラッグ・右クリック・スクロールの判定を表示します。操作停止中もプレビューで判定を確認でき、その間はマウスイベントを送りません。映像が途切れると骨格表示を消します。

認識処理はMacのApple Vision（`VNDetectHumanHandPoseRequest`）で行います。THINKLETはJPEG映像をUSBで送信し、Macで回転した画像から関節と手の左右を推定します。表示用の反転は映像・骨格・操作座標に一緒に適用します。親指と指先の距離を手の大きさで正規化し、つまんだ時間と移動から操作を区別します。

キー入力を検出するとマウス操作を停止し、ドラッグ中のボタンも解除します。最後のキー押下・解放から1.2秒待ち、親指を離した状態を確認すると再開します。キーの内容を記録・保存しません。他アプリのキー検出にはmacOSの許可が必要で、入力イベントを受け取れない環境や保護された入力中は自動停止を保証できません。その場合は「操作停止」を使用してください。

イベント監視に加えてキーの押下状態・直近の入力時刻を確認します。また、実際のキー入力と同時に映った指先の位置を3回以上取得すると、キーボードの範囲を自動学習します。「キーボード範囲で停止」がオンの場合、黄色い枠にどちらかの手の指が入ると、キーを押していない間も停止します。枠から指が0.4秒以上離れ、その後につまみが開いていることを確認して再開します。枠が合わない場合は「キーボード範囲を指定」を押し、映像内のキーボードを囲む2つの角をクリックしてください。「学習をリセット」で解除します。カメラの回転変更でも範囲を解除します。範囲は起動中のみ保持します。v0.10の手首モードでは、キーボードの近くで使えるよう範囲停止を初期設定でオフにしています。実際のキー入力による停止は引き続き有効です。

この判定は映像内の範囲との重なりを使うため、実際の接触・高さは分かりません。キーボードの上空でも停止することがあり、キーボードが映らない状態では範囲による停止はできません。未学習の間はキー入力のみを使います。カメラの位置を動かした場合は範囲を設定し直してください。

### 許可したのに動かない場合

v0.5以降は、画面の `AX`（アクセシビリティ）、`Post`（イベント送信）、`Listen`（入力監視）を個別に表示します。以前の版はAXとPostの両方を必須にしていたため、片方だけ許可されている状態でも開始できませんでした。AXまたはPostが許可されていれば開始できるように修正しています。実際のイベント送信は引き続きmacOSの許可で制御されます。Listenだけでは操作を開始しません。

両方とも未許可の場合は「診断情報をコピー」で、実行中のアプリの場所、バージョン、macOSの各許可判定、映像・認識の状態をコピーして確認できます。入力したキーの内容やカメラ画像は含みません。設定の登録先と実行中のアプリの場所が一致するかも確認してください。開発版の署名変更に伴う古い登録や、反映待ちの可能性はありますが、許可エラーだけでは原因を断定しません。「アクセシビリティ設定」は必要に応じてmacOSの操作許可を要求して設定を開きます。入力検出には「入力監視設定」も確認してください。権限はアプリが勝手に変更しません。

`/Applications` に移動したアプリは、プロジェクト内のビルドでは更新されません。更新後は既存アプリを終了し、生成されたアプリでインストール先を置き換えてください。画面のバージョンと「診断情報をコピー」の実行パスで、実際にどの版を開いているか確認できます。

v0.6の「ポインター動作テスト」は、手の操作を一時停止して、現在のディスプレイでポインターを横に160ポイント移動します。1.5秒後に開始・要求・応答のOS座標を記録し、元の位置には戻しません。OS座標の変化と、画面で実際に見えた移動は区別して表示します。テスト前に操作オンだった場合は、安全条件を満たせばオンに復帰します。元がオフならオフのままなので、手で動かすには「操作開始」を押してください。停止ボタン・Esc・再接続・設定変更でテストを中止した後は、自動で再開しません。

画面最上部に操作オン／オフと停止理由を表示します。診断には、テスト直前のオン／オフ、最後の停止理由、出力イベント数、最後の出力も含めます。v0.5までのテストは0.15秒で元の位置に戻したうえ、操作をオフのままにしていたため、目視しづらく、テスト後の停止状態と権限問題を取り違える可能性がありました。

権限エラーはダイアログで表示し、画面の更新で消えないようにしています。左上隅への緊急停止は、アプリ自身の移動で左上隅に到達した場合には発動しません。

手が横向きで指が重なる場合、手のひらの投影幅を使って操作を抑制し、向きを変える案内を表示します。中指や薬指の一部が見えなくても、必要な関節が見えていればポインター移動・左クリック・ドラッグは可能です。隠れた指を確実に復元する機能ではなく、単眼画像での誤クリックを減らすための判定です。任意の向きでの認識には別モデルやカメラ配置の検討が必要で、現在の幅の閾値も実機調整が必要です。

接続に失敗した場合は、USB接続を確認してアプリの「再接続」を押してください。エラー欄にカーソルを置くと詳細ログを表示します。アプリには接続スクリプトとAPKを同梱しています（ADBはMac側に必要です）。通常の起動先は `/Applications` に固定します。

USBデバッグが未承認の場合は端末の承認が必要です。複数端末がある場合や自動判別できない場合は `THINKLET_SERIAL=端末ID ./scripts/connect.sh --prepare` で接続を設定してからアプリを開きます。端末IDは `adb devices -l` で確認します。

## ジェスチャー

| 操作 | 手の動き |
| --- | --- |
| ポインター移動 | 人差し指を動かす。相対移動と速度に応じた加速 |
| 左クリック | 親指と人差し指をつまんで離す（最短約0.06秒）。手が静止していれば長めでもクリック |
| ダブルクリック | 短いつまみを2回。Macのダブルクリック間隔内で行う |
| ドラッグ | 親指と人差し指を0.45秒以上つまみ、手を明確に動かす。離すとドロップ |
| 右クリック | 親指と中指を短くピンチし、左右に動かさず離す（約0.06〜0.35秒） |
| スクロール | 親指と中指をピンチしたまま手を左右へ。映像上で右に動かすと下、左に動かすと上 |
| 一時停止 | アプリの「操作停止」、Esc、または⌘⇧P |
| 緊急停止 | 物理マウスをメイン画面の左上隅へ動かす |

中指ピンチ中はポインターを固定します。手首が映像幅の約1.8%以上左右に移動するとスクロールに切り替わり、そのピンチを離しても右クリックは発生しません。上下移動ではスクロールしません。手を見失った場合や入力・キーボード範囲で停止した場合も、保留中の右クリックを破棄します。

v0.10は「手首で操作」が初期設定です。腕を机に置いたまま、手首の向きを少し変えて使います。ポインターには手首から人差し指先へのベクトル、ドラッグとスクロールには手首から人差し指・中指の付け根へのベクトルを使います。画像の縦横比を補正し、手首から中指の付け根までの長さで正規化して、カメラからの距離の影響を抑えます。v0.11では手の幅の変化や小指の付け根の見失いで座標が跳ねる問題を修正し、速い移動から減速したときは加速をすぐ落として狙いやすくしました。腕全体の移動はこのモードでは差し引かれます。スクロール・ドラッグの移動閾値も手に対する向きの座標で判定します。

「この姿勢を基準にする」で現在のカーソル位置から基準を取り直せます。手首モードの感度は従来の画像移動モードとは別に保存し、初期値は100%です。以前の250%設定をそのまま流用しません。「手首で操作」をオフにすると従来の移動方式に戻せます。2D画像からの推定なので、指が隠れる向きや手首を奥行き方向にだけ回す動きは区別しづらく、実際の装着姿勢での調整が必要です。

「ポインター」「スクロール」のスライダーで感度を個別に変更できます。ポインターは40〜250%、スクロールは25〜300%で、初期値は100%です。値はMac内に保存して次回起動時に復元します。ポインターの感度を上げると、同じ手の移動量で動く画面上の距離が増えます。変更時は操作をリセットするので、一度ピンチを開いて再開してください。

v0.9では「加速」のスライダーを独立して追加しました（0〜300%、初期値150%）。加速0%は速度によらず一定の感度です。初期設定では、映像上で毎秒4%以下のゆっくりした移動は基準感度のまま、毎秒4〜40%の移動で滑らかに倍率が増え、毎秒40%以上では基準感度の7倍を上限にします。加速を強くしても低速時の基準感度は変わりません。加速の設定も保存されます。これらは平滑化後の速度に対する内部の倍率で、実際の移動距離には画面端や補間も影響します。

操作範囲はメインディスプレイです。v0.8からは、現在のカーソル位置を基準にした相対移動です。手を映し直した時も、指先の位置へ突然飛びません。ゆっくり動かすと低い感度、速く動かすと高い感度で移動します。入力座標を平滑化し、カメラ認識とは別の60Hzタイマーで目標位置へ補間します。映像が古くなった場合は補間を中止し、先読みで動かし続けません。

親指と人差し指が近づく動きを検出すると、接触前から短時間カーソルを固定します。ピンチ中と解放後0.12秒も固定し、指を離したときの位置ずれを抑えます。ドラッグには保持時間に加えて手首の移動（映像座標で距離0.025以上）が必要です。指先だけが曲がってもドラッグにならず、開始後は手首の移動を使って運びます。

物理マウス・トラックパッドの移動、ボタン、スクロールを検出すると、手の操作と補間を即座にキャンセルします。物理ボタンを押している間と、最後の入力後1.5秒は物理入力を優先します。再開時は現在のカーソル位置を基準にし、ピンチを開いてから操作を受け付けます。アプリ自身の送信イベントには識別タグを付け、物理入力と区別します。物理左ボタンが押されている場合は、手のドラッグ解除でそのボタンを勝手に解放しません。入力イベントを受信できる権限が必要です。

「右手のみ／左手のみ」で操作する手を選べます（初期設定は右手）。最大2つの手を検出し、選択した側の手だけを描画・操作に使います。左右を判断できない手は操作に使いません。左右判定は表示用の反転前に行います。設定変更時は操作を停止するため、再度「操作開始」を押してください。左右判定の精度は実機での確認が必要です。

手の見失い・映像の停止でドラッグを解除します。手を隠す動作は**一時停止ではなくボタン解放**です。再び映すと操作を再開します。Escのグローバル監視が許可されていない場合でも停止ボタンと左上隅停止が使えます。

終了時はMacアプリを⌘Qで閉じます。THINKLET側のカメラも終了させる場合は `THINKLET_SERIAL=端末ID ./scripts/stop.sh` を実行します。USBを抜くだけではTHINKLET側のカメラアプリは終了しません。

## 構成・実装計画

1. THINKLET（Android 8.1対応）で対応サイズのうち960×720に近い解像度、JPEG品質85、最大約15fpsでJPEG化する。
2. 端末内127.0.0.1:8765のみにHTTPサーバーを置き、ADBでMacの127.0.0.1:18765へ転送する。
3. MacのApple Visionで21関節を検出し、手の大きさで正規化した指間距離からつまみを判断する。
4. 状態機械でクリック・ドラッグ・スクロールを判別し、Quartzでマウスイベントを送る。
5. 手の消失・接続切れ・停止・終了時にボタンを解放する。

映像はローカルでのみ処理します。録画・音声収集・クラウド送信を実装していません。Android側は旧THINKLETとの互換性のためCamera APIを使用しています。

## ビルドと検証

必要環境：macOS 12以降、Xcode/Command Line Tools、Android StudioのJDK、Android SDK platform 35 / build-tools 35.0.0、ADB。

```sh
./scripts/build.sh
xcrun swiftc -module-cache-path build/swift-cache mac/GestureEngine.swift tests/main.swift -o build/test-gestures
./build/test-gestures
```

Android SDKの位置は `ANDROID_HOME`、Javaの位置は `JAVA_HOME` で変更できます。MediaPipeの追加インストールは不要です。ビルド・インストールにはPython 3を使用します。APKはこの作業フォルダ専用の開発鍵で署名しています。

Macアプリはv0.7から、`.local-signing` のプロジェクト専用証明書で署名する構成です。証明書と暗号化した秘密鍵を保持し、アプリIDと証明書の指紋を固定したdesignated requirementで署名します。以前の要件と異なる場合やキーチェーンが未設定の場合は、アドホック署名へ戻さず停止します。キーチェーンの作成・鍵のインポートは通常のMac環境で `Install.command` から実行してください。グローバルな証明書の信頼設定やTCCデータベースは変更しません。

`.local-signing` を失うと同じ署名を維持できません。外部へ公開せず、保管してください。秘密鍵・パスワードはアプリに同梱しません。更新はステージングしたアプリを検証してからインストール先へ配置し、置き換え失敗時は旧版を復元します。旧版の控えは `build/previous-installed-app.app` に保存します。

## 検証状態と制限

- Android APKとMacアプリのビルド成功。
- 105項目の自動テスト成功（手首方向の平行移動・拡大縮小への不変性、手の幅の揺れ・小指関節の見失いによる座標ずれの防止、腕を止めた移動・ドラッグ・スクロール、低速精密操作・高速加速、物理マウス優先、補間・クリック固定、既存ジェスチャー・権限・キーボード判定など）。
- インストーラーの更新・失敗時復元を4項目、署名要件の継続性と不正なフォールバック防止を6項目のユニットテストで確認しています。これらは署名ツールの実動作やTCC許可の継続を検証したものではありません。
- 現在のエージェント実行環境では署名用キーチェーン作成が拒否されるため、証明書署名によるインストール全体は未検証です。署名・検証失敗時は旧版を更新しない構成にしています。
- 指の距離は映像の縦横比を補正して計算します。フレームIDで重複映像を除外し、認識の連続回数に重複を数えません。ポインターには時間と速度に応じた平滑化と微小な揺れの抑制を適用します。これらは認識率の定量的な改善を実証したものではありません。
- この実装環境ではADBのローカル通信待受が `Operation not permitted` で拒否されるため、実機へのインストール・映像取得・実際のマウス操作は未検証。
- 首掛けカメラでの認識率、レンズの向き、使いやすいつまみ閾値、遅延は実機での調整が必要。照明、手の遮蔽、装着時の揺れに影響されます。
- 実機動作の確認前は、重要なファイルを操作しない画面でお試しください。
